# 朱佳明个人博客改版说明书

> 版本：v1.0（实施前基线）  
> 状态：待确认  
> 适用项目：`E:\code\blog`  
> 核心目标：从“企业产品式作品集”改为“有技术内容、项目证据和个人气质的开发者博客”。

## 1. 文档作用

本说明书用于冻结下一版网站的目标、边界和验收口径。正式开发不得因为某个参考网站局部好看，就临时改变整站结构或增加无关功能。

除修复编译错误、明显可访问性问题和事实错误外，实施阶段出现的新想法统一记录到“后续候选”，不直接扩大本轮范围。

## 2. 网站定位

网站首先服务于面试官和技术同行，其次才是长期博客读者。

访客进入网站后，应在短时间内回答四个问题：

1. 朱佳明是谁，目前在做什么？
2. 他真正完成了哪些项目？
3. 项目中承担了什么工作，有什么可验证证据？
4. 如何查看源码、阅读技术笔记或联系本人？

网站不定位为企业产品官网、在线简历生成器、论文主页，也不包装成已经商业化或上线运营的 Agent 平台。

## 3. 目标用户与核心任务

### 3.1 面试官 / 招聘者

- 5 秒内识别姓名、身份、求职方向和技术主题。
- 30 秒内看到 EvoAgent 与 OA Evidence Agent 的差异。
- 2 分钟内找到职责、架构、测试证据、能力边界和公开源码。
- 快速获得邮箱、GitHub 等联系方式。

### 3.2 技术同行

- 了解 Agent Runtime、工作流、RAG、评测和可观测性等实现思路。
- 阅读项目复盘文章。
- 从项目详情进入可公开访问的源码。

### 3.3 长期读者

- 浏览近期技术笔记。
- 通过清晰的分类和 RSS 持续阅读。

## 4. 参考来源与使用比例

本轮不是复刻任何单一网站，而是提取不同参考的明确职责。

### 4.1 liruifengv：结构与中文个人感（40%）

参考页面：<https://liruifengv.com/about/>

借鉴：

- 首页、文章、项目、关于四个主要入口。
- 技术栈、开源经历、联系方式以普通内容呈现，而非营销口号。
- 博客和个人主页融合，而不是两个割裂的网站。

不照搬：

- 现成文案、组件造型、品牌标识与具体版式尺寸。

- Projects / Writing 的直接层级。

- 项目预览图作为项目入口，而不是堆砌大量功能标签。

不照搬：

## 5. 内容与事实边界

### 5.1 项目范围

本轮只重点展示两个项目：

- EvoAgent
- OA Evidence Agent

其他练习项目、课程作业和未经核验的概念暂不进入首页。

### 5.2 EvoAgent 表述边界

- 可以描述为面向 GitHub PR 的可验证多智能体代码审查平台。
- 可以展示 58 / 58 自动化测试通过。
- 100 个 Diff 及相关指标必须标注为“受控合成评测”。
- 不得把受控数据描述成真实公开 PR 或生产环境效果。
- “演进”只表示 Prompt 与声明式 Skill 版本演进，不表示训练模型或修改权重。
- 自动修复必须说明是保守白名单、独立分支与 Draft PR 流程。

### 5.3 OA 表述边界

- 定位为膝骨关节炎证据增强研究型 AI Agent，不定位为诊断系统。
- 后端测试使用真实口径：166 passed、1 skipped；前端为 35 / 35。
- BioMedCLIP 输出只能描述为研究级图文余弦相似度候选。
- 不使用“诊断概率”“医学置信度”“KL 准确率”“临床验证”等表达。
- Claim 检查不写成事实认证；规则安全检查不写成临床安全认证。
- 6 条 NICE / AAOS 内容应写成带来源信息的项目自撰短摘要，不写成大型医学知识库。
- OA 匿名 GitHub 链接未公开前，页面只显示“仓库待公开”，不提供 404 链接。

### 5.4 通用真实性规则

- 不虚构访问量、Star、用户数量、上线时间、团队规模和生产部署。
- 动态架构图标记为 Architecture Walkthrough，不伪装成本次真实后台 Trace。
- 示例界面不得使用假的病例编号、置信度或评测成绩制造真实运行印象。
- 所有数字必须能追溯到源码、测试或明确标注的数据来源。

## 6. 信息架构

主导航固定为：

```text
首页 / 项目 / 文章 / 关于 / GitHub
```

“技能”和“研究”不进入主导航。原有 `/skills`、`/research` 可保留兼容入口，但内容合并到 About；后续可选择重定向。

### 6.1 首页

首页顺序固定为：

1. 个人 Hero
2. 精选项目
3. 最新文章
4. 简短 About
5. 联系方式与页脚

首页不再单独放置三张抽象能力卡、企业式指标墙和大段产品卖点。

#### Hero

- 主标题使用自然中文，直接说明姓名和方向。
- 显示东华大学计算机硕士、AI Agent 开发实习方向。
- 主操作：查看项目。
- 次操作：GitHub、联系我。
- 右侧或标题附近只保留一个 Agent 主题互动对象。

#### 精选项目

- 两个项目纵向排列，一次突出一个。
- 每项包含：项目名、一句话价值、个人工作、2–3 条证据、技术栈、详情入口。
- EvoAgent 显示公开 GitHub；OA 未公开前显示状态文本。
- 项目视觉优先使用原创的简洁架构 walkthrough；未来有真实录屏后再替换。

#### 最新文章

- 当前只展示两篇真实项目文章。
- 一篇作为主文章，一篇作为次文章，避免空洞的多列内容门户。
- 草稿与占位文章不出现在生产页面、RSS 和站点地图中。

### 6.2 项目列表

- 不提供筛选器，因为只有两个项目。
- 项目列表是进入详情页的简洁索引，不重复详情页全部内容。

### 6.3 项目详情

统一结构：

1. 项目定位与状态
2. 问题与约束
3. 我的工作
4. 系统流程
5. 关键技术决策
6. 验证证据
7. 能力边界
8. 技术栈与源码状态
9. 相关文章

详情页控制在 3–5 分钟可读完，不复制 README 全文。

### 6.4 文章页

- 保持适合中文长文阅读的窄正文宽度。
- 支持目录、发布时间、标签、上一篇 / 下一篇。
- 项目文章可互相链接到对应项目详情。

### 6.5 About

- 采用 liruifengv 的自然中文叙述方式。
- 包含个人介绍、教育经历、正在关注的问题、技术能力、两个项目、联系方式。
- 技能不使用百分比或进度条，以项目证据说明。
- 暂时不展示头像；没有真实照片时不生成 AI 人像替代。

## 7. 视觉系统

### 7.1 整体气质

关键词：

```text
自然 / 克制 / 清楚 / 有一点趣味 / 可信 / 非企业官网
```

### 7.2 色彩

- 浅色模式为默认：暖白背景、接近黑色的正文、柔和灰色辅助文字。
- 紫色作为主强调色；绿色只用于成功、公开状态或 OA 的轻量区分。
- 不使用大面积霓虹、玻璃拟态、强渐变背景和发光边框。
- 深色模式保留，但不得影响浅色模式的首要设计质量。

### 7.3 字体与排版

- 中文正文优先使用系统中文字体，保证加载与可读性。
- 英文、数字、代码可使用现有等宽字体栈。
- 标题不追求超大字号；首屏标题在常见笔记本屏幕中应完整可见。
- 正文行长约 60–75 个英文字符，中文正文保持舒适宽度。
- 统一间距比例，避免每个区块使用不同的设计语言。

### 7.4 图形语言

- 项目流程图使用 HTML / CSS 和少量简单线条，不绘制复杂模型生成 SVG。
- 手绘元素只作为批注，不承担关键信息。
- 不使用假的软件截图；未来使用真实截图时必须标明对应版本或运行状态。

## 8. 动效边界

全站动效预算固定为：

- Hero：1 个核心互动。
- 每个项目：1 个轻量流程动效。
- 文章和普通卡片：仅 hover、focus 和短进入反馈。

明确禁止：

- 滚动劫持、强制视差和鼠标跟随光标。
- 自动播放带声音的媒体。
- 每个区块分别使用不同动画风格。
- 动画表达关键信息而没有静态替代。
- 为模仿 Josh W. Comeau 而引入完整游戏化系统。

技术约束：

- 默认优先 CSS 动画。
- 单个互动需要复杂状态时，才允许引入一个小型 Astro Island。
- 所有动画支持 `prefers-reduced-motion`。
- 触控设备不依赖 hover 才能访问内容。

## 9. 技术实施边界

- 保留现有 Astro、内容集合、Tailwind 和静态生成架构。
- 不为了视觉改版迁移到 Next.js、Vue 或完整 React SPA。
- 不引入数据库、登录、评论、CMS、搜索服务和在线编辑器。
- 不修改 EvoAgent 与 OA 项目仓库源码。
- 本轮不处理正式域名和简历内容。
- 本轮不负责公开 OA 仓库；只根据公开状态调整链接。
- 未经确认不改变 Vercel 访问权限或域名设置。
- 开发从新分支 `codex/portfolio-redesign-v2` 开始，避免直接在稳定的 `master` 上试错。

## 10. 性能、响应式与可访问性

### 10.1 性能目标

- 静态页面保持为主，不引入不必要的客户端 JavaScript。
- 首屏不加载大视频或高分辨率装饰图。
- 新增图片使用正确尺寸、压缩格式与懒加载策略。
- 生产构建不得出现错误或警告。

### 10.2 响应式

- 最小支持宽度 320px。
- Hero、项目卡、流程图在窄屏改为单列。
- 不出现页面级横向滚动。
- 移动端触控目标不小于约 44×44px。

### 10.3 可访问性

- 每页仅一个 `h1`。
- 键盘可访问所有导航、按钮与互动对象。
- 保留跳到正文、焦点样式、语义化标题和 `aria-current`。
- 色彩不作为唯一状态信号。
- 互动视觉提供可读说明或静态等价内容。

## 11. 明确不做的内容

本轮不做：

- 企业 SaaS 风格大屏、仪表盘或指标墙。
- 完整复刻任何参考网站。
- AI 生成头像、虚构项目截图和大量装饰插画。
- 3D、WebGL、粒子背景和复杂鼠标特效。
- 博客评论、点赞、账户、订阅邮件和后台 CMS。
- 论文管理、知识图谱或 Maggie 式完整数字花园。
- 多语言版本。
- 新域名、正式简历、OA 仓库发布和 Vercel 权限调整。
- 为填充版面新增低质量占位文章。

## 12. 实施顺序

### 阶段 A：建立视觉基线

1. 创建独立分支。
2. 收敛全局色彩、字体、宽度、间距和按钮样式。
3. 只修改首页首屏和一个项目预览，形成最小可判断样稿。
4. 本地编译成功后展示，确认方向再扩展其他页面。

### 阶段 B：完成主要页面

1. 完成首页其余区域。
2. 重做项目列表和两个详情页。
3. 统一博客、文章和 About。
4. 收敛旧技能、研究页面。

### 阶段 C：验证与发布准备

1. 类型检查与生产构建。
2. 核对事实、链接和仓库公开状态。
3. 检查移动端、键盘操作、减少动画和内部路由。
4. 对比说明书逐项验收。
5. 经确认后再提交、推送并触发部署。

## 13. 验收标准

只有同时满足以下条件，改版才视为完成：

### 内容

- 首屏清楚展示姓名、身份、方向与主要操作。
- 首页只重点展示 EvoAgent、OA 和两篇真实文章。
- 项目数据与已核验源码一致。
- OA 没有越过医疗研究边界。
- 页面中没有占位文案和失效公开链接。

### 视觉

- 整站看起来属于同一个设计系统。
- 不再呈现企业产品落地页气质。
- 至少有一个自然的个人记忆点，但不压过项目内容。
- 浅色、深色和移动端均能清晰阅读。

### 交互

- Hero 核心互动工作正常，静态状态也可理解。
- 动画减少模式下无持续动画。
- 所有关键操作支持键盘与触控。

### 工程

- `astro check` 为 0 errors、0 warnings、0 hints。
- 生产构建成功。
- 主要 HTML 页面均只有一个 `h1`。
- 所有站内路由与静态资源可解析。
- 开发服务器按项目约定使用后台模式启动并在验收后停止。

## 14. 风险与取舍

### 风格混合风险

Josh 与 Maggie 的活泼元素必须服从 liruifengv 的结构和 Emil 的视觉系统。任何新增互动如果无法用同一套颜色、圆角、运动节奏表达，就不进入本轮。

### 内容不足风险

当前真实文章只有两篇，因此不构建大型内容门户。首页优先展示项目，文章区域保持精简，等积累更多高质量文章后再扩展。

### 项目证据与页面美观冲突

首页只展示最重要证据，详细测试数字和边界放在详情页。不能为了简洁删除关键限定，也不能把全部 README 塞进首页。

### 动效成本风险

先实现静态可读版本，再加入核心互动。若互动明显拖慢页面、影响移动端或无法无障碍降级，则删除互动而不是降低工程质量。

## 15. 后续候选，不属于本轮

- 使用真实录屏替换项目 walkthrough。
- 正式头像或个人摄影。
- OA 仓库公开后的 GitHub 接入。
- 正式简历和域名。
- 文章搜索、系列和更多分类。
- 项目时间线或独立实验页面。

## 16. 开工条件

本说明书确认后，实施阶段默认遵守以下约定：

1. 不再重新选择整站参考方向。
2. 首次只交付首页首屏与一个项目预览作为视觉基线。
3. 基线确认后再完成整站。
4. 超出本说明书的功能进入后续候选，除非明确重新调整范围。
